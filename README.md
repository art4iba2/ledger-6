# Ledger и Gateway

Gateway предоставляет HTTP API на `:8080` и вызывает импортируемый модуль
`ledger` из соседней папки. Связь модулей задана в `gateway/go.mod` через
`require ledger v0.0.0` и `replace ledger => ../ledger`.
Внешних зависимостей нет. Требуется Go 1.20 или новее.

## Запуск в Windows CMD

Все команды ниже предназначены для командной строки **CMD (cmd.exe)**.
Откройте CMD в корневой папке проекта и выполните:

```cmd
chcp 65001
cd gateway
go run .
```

Оставьте сервер работающим. Для запросов откройте второе окно CMD
и также выполните `chcp 65001`, чтобы работать с русским текстом.
Остановить сервер можно сочетанием `Ctrl+C`.

Один экземпляр Ledger хранит данные в памяти. При запуске списки пусты;
после перезапуска данные теряются. Gateway синхронизирует обращения
к хранилищу, чтобы параллельные запросы не обходили лимит бюджета.

## Эндпоинты

| Метод | Путь | Ответ при успехе |
| --- | --- | --- |
| POST | `/api/transactions` | 201, созданная транзакция |
| GET | `/api/transactions` | 200, массив транзакций |
| POST | `/api/budgets` | 201, созданный или обновлённый бюджет |
| GET | `/api/budgets` | 200, массив бюджетов |

Пустые списки возвращаются как `[]`. Для всех ответов установлен
`Content-Type: application/json; charset=utf-8`.
Ошибки имеют вид `{"error":"описание"}`:

- 400 — некорректный JSON или ошибка доменной валидации;
- 409 — превышение бюджета, `{"error":"budget exceeded"}`;
- 500 — непредвиденная внутренняя ошибка;
- 404 — неизвестный путь;
- 405 — неподдерживаемый метод, с заголовком `Allow: GET, POST`.

Сумма и лимит должны быть конечными положительными числами,
категория не должна быть пустой или состоять из пробелов.
`description` и строковая `date` сохраняются и возвращаются клиенту;
проверка формата даты опущена, как в предыдущем задании.
Тело ограничено 1 МиБ, допускается один JSON-объект без неизвестных полей.
Бюджет действует на всю историю категории. Достижение лимита разрешено,
категории без бюджета не ограничены. Повторный POST бюджета обновляет лимит.

## Проверка через cURL в Windows CMD

Копируйте каждую команду целиком в одну строку. В CMD аргументы заключают
в двойные кавычки, а кавычки внутри JSON экранируют как `\"`.
Одинарные кавычки из примеров для Linux здесь использовать нельзя.
Для переноса команды на следующую строку в CMD служит `^`, а не `\`;
после `^` не должно быть пробелов.

Примеры рассчитаны на только что запущенный сервер с пустым хранилищем.
Выполняйте их по порядку: повторное создание транзакций увеличивает расходы.

Создать бюджет (201 Created):

```cmd
curl.exe -i -X POST http://localhost:8080/api/budgets -H "Content-Type: application/json" -d "{\"category\":\"еда\",\"limit\":500}"
```

Добавить транзакцию (201 Created):

```cmd
curl.exe -i -X POST http://localhost:8080/api/transactions -H "Content-Type: application/json" -d "{\"amount\":450,\"category\":\"еда\",\"description\":\"ланч\",\"date\":\"2025-09-10\"}"
```

Превысить бюджет (409 Conflict); транзакция не сохранится:

```cmd
curl.exe -i -X POST http://localhost:8080/api/transactions -H "Content-Type: application/json" -d "{\"amount\":100,\"category\":\"еда\",\"description\":\"кофе\",\"date\":\"2025-09-10\"}"
```

Ожидаемое тело ошибки:

```json
{"error":"budget exceeded"}
```

Получить списки (200 OK). В списке транзакций должна остаться только
успешная транзакция на 450 рублей:

```cmd
curl.exe -i http://localhost:8080/api/transactions
curl.exe -i http://localhost:8080/api/budgets
```

Некорректный бюджет (400 Bad Request); прежний лимит 500 сохранится:

```cmd
curl.exe -i -X POST http://localhost:8080/api/budgets -H "Content-Type: application/json" -d "{\"category\":\"еда\",\"limit\":0}"
```

Обновить бюджет (201 Created):

```cmd
curl.exe -i -X POST http://localhost:8080/api/budgets -H "Content-Type: application/json" -d "{\"category\":\"еда\",\"limit\":1000}"
```

Та же команда с переносами строк для CMD:

```cmd
curl.exe -i -X POST http://localhost:8080/api/budgets ^
  -H "Content-Type: application/json" ^
  -d "{\"category\":\"еда\",\"limit\":1000}"
```

Если появляется `invalid JSON: EOF`, проверьте, что запрос содержит `-d`
с JSON-телом. Ошибки `Bad hostname`, `Could not resolve host: application`
и `invalid character '\''` в показанных ранее командах связаны с кавычками
или переносами строк: используйте приведённые выше команды для CMD.

Middleware логирует метод, путь и длительность каждого запроса в консоль.
HTTP DTO и преобразователи находятся в `gateway/internal/api/dto.go`;
доменные модели и бизнес-проверка бюджета остаются в Ledger.

## Тесты и покрытие

Из корня репозитория в Windows CMD запустите:

```cmd
powershell.exe -NoProfile -File scripts\test-coverage.ps1
```

Скрипт последовательно запускает тесты двух модулей, создаёт в каждом
`cover.out` и `cover.html`, выводит покрытие функций и обновляет проценты
в этом README. README обновляется только после успешного выполнения
обоих наборов тестов. Для запуска необходим установленный Go.

Те же действия вручную в CMD, начиная из корня репозитория:

```cmd
cd ledger
go test ./... -v -cover -coverprofile=cover.out
go tool cover -html=cover.out -o cover.html
go tool cover -func=cover.out
cd ..\gateway
go test ./... -v -cover -coverprofile=cover.out
go tool cover -html=cover.out -o cover.html
go tool cover -func=cover.out
cd ..
```

Открыть HTML-отчёты после успешного запуска:

```cmd
start "" ledger\cover.html
start "" gateway\cover.html
```

Покрытие учитывает все пакеты каждого модуля, включая консольные
точки входа `main`; это не только покрытие домена или HTTP-пакета.
Строка `total` команды `go tool cover -func=cover.out` показывает итог
для соответствующего модуля.

Ledger: табличные unit-тесты `Transaction.Validate` и `Budget.Validate`,
проверка интерфейса, обновление бюджета, достижение и превышение лимита,
отказ без сохранения, списки, очистка и загрузка JSON.
Независимые проверки валидации и добавления выполняются через `t.Parallel()`.

Gateway: интеграционные тесты в `gateway/internal/api/handlers_test.go`
используют `httptest.NewRecorder` и `httptest.NewRequest` с настоящим Ledger.
Сценарии сгруппированы через `t.Run`: `ok`, `exceeded`, `bad_json`,
`zero_limit`, `negative_limit`. Проверяются JSON DTO, списки, статусы,
заголовок Content-Type, сохранность данных при отказе, внутренние ошибки,
логирование и параллельные запросы.

Глобального состояния в Ledger нет. Метод `(*Ledger).Reset()` очищает
транзакции и бюджеты конкретного экземпляра. Тестовые помощники создают
экземпляр для каждого сценария и регистрируют `t.Cleanup(book.Reset)`.
HTTP-подтесты не запускаются параллельно; тест конкурентных запросов
дожидается завершения всех горутин до очистки.

При настроенном CGO и совместимом C-компиляторе дополнительно запустите
`go test -race ./...` из папки каждого модуля.

Для импорта Ledger его пакет преобразован из `main` в `ledger`;
прежний консольный пример перенесён в `ledger/cmd/demo`.
Запуск примера из папки `ledger`: `go run ./cmd/demo`.
